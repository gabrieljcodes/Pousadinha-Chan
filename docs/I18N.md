# Bot localization and slash commands

The Discord bot uses [go-i18n v2](https://github.com/nicksnyder/go-i18n). English is
the first supported language. `BOT_LANGUAGE=en` selects the process's message
language; unsupported preferences fall back to English. Language selection is
immutable after startup. No database migration is needed for this change.

## Catalogs

`internal/locale/messages/*.en.json` groups messages by domain: commands, games,
gacha, markets, webhooks and shared presentation. These JSON catalogs are embedded
in the binary, loaded once and shared by immutable localizers. User-authored
content, imported character/work names, SQL, logs, IDs and persisted enum values
are not translation keys. Existing Portuguese animal input aliases remain valid
for stored lottery data and input matching; their display names are English.

Use a stable message ID and named template data:

```go
locale.Text("common.server_only")
locale.Text("gacha.discord.harem_page.formatted", locale.Data{"Page": page})
locale.Plural("gacha.wishlist.count", count, locale.Data{"Count": count})
```

Templates use standard Go template syntax. For example:

```json
{
  "gacha.wishlist.count": {
    "one": "{{printf \"%d\" .Count}}/20 wished character",
    "other": "{{printf \"%d\" .Count}}/20 wished characters"
  }
}
```

Keep named fields and their types intact when translating. Most dynamic messages
use named fields; a few error/builder messages retain printf verbs to preserve
error wrapping or streaming output. Those verbs must retain their types and
argument order (or use explicit indexed verbs). A missing message or required
field is a programming error, caught by catalog tests before deployment.

To add a language, create a matching domain file such as `gacha.pt-BR.json`, retain
its message IDs, and translate its forms. The bundle discovers embedded JSON files
automatically. Rebuild and set `BOT_LANGUAGE=pt-BR` to use that language for the
bot. Missing translations fall back to English. `locale.FromInteraction(i)`
extracts the invoking user's language (and guild locale) per request, and
`ApplicationCommands()` automatically populates Discord's `DescriptionLocalizations`
and `NameLocalizations` from any loaded non-English catalogs (e.g. `pt-BR`).

Command names/options remain stable English protocol identifiers. Descriptions
and choice labels come from the catalog and are localized per user via Discord API.

## Slash-only migration

Message-prefix dispatch and its handlers have been removed. The bot no longer
requests Message Content or Guild Messages intents. Games continue through slash
interactions, buttons and modals. Guilds and voice-state intents remain enabled.
All commands reject DMs and are registered as guild-only commands.

The startup bulk overwrite replaces global slash registrations, including the
old Portuguese names. Restart the bot to apply the command registration change.
If registration fails, startup logs the error; resolve it before expecting the
new catalog to appear. Previously installed guild-specific command registrations
are outside the global overwrite and must be removed from their original guild
scope if you created any manually.

Canonical gacha names include `/profile`, `/gallery`, `/trade`, `/gift` and
`/divorce`. `/keys`, `/search`, `/harem-ranking` and `/offers` expose discovery and
management features without text-command fallbacks. See [Gacha commands](GACHA_COMMANDS.md).

Server event betting uses `/event create`, `list`, `view`, `bet`, `close`, `result`
and `cancel`. Creation requires Administrator or Manage Server. Management
requires the event creator or one of those permissions; every event operation
checks the current guild. The creation `options` field accepts 2–10 choices
separated by `|`; `duration` is in minutes (default 60, maximum 1440).

Economy, shops, loans, casinos, stock/crypto trading, animal lottery, Polymarket,
API keys and webhooks retain their slash interfaces. `/help` lists the supported
commands and their button-driven flows.

## Validation

```sh
go test ./internal/locale ./internal/commands ./internal/games
GACHA_TEST_DATABASE_URL='postgres://postgres:test@localhost:55442/gacha_test?sslmode=disable' go test -race ./...
go build ./cmd/bot ./cmd/catalog ./cmd/gacha
```

The catalog tests check missing/unused IDs, required template fields, rendering,
fallback and plural forms. Command tests validate unique English identifiers,
Discord description/choice limits, option ordering, guild-only registration and
gacha request mapping. Event tests reject cross-guild access and unauthorized
management without contacting Discord. PostgreSQL tests cover the existing game
transactions and wishlist rendering against the migrated schema.
